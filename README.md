# FaceMosaic Browser（v2）

動画の顔を自動で見つけて追いかけ、顔だけにモザイクをかける **ブラウザだけで動く静的Webアプリ**です。
サーバー側のプログラムは不要で、**ファイルを置くだけ**で動きます（GitHub Pages、さくらのレンタルサーバ、手元のPC）。

- 動画は利用者のパソコンの中だけで処理され、**外部には送信されません**
- 顔検出は YuNet（dynamic-input 版 `face_detection_yunet_2026may.onnx`）。追跡・モザイクは、デスクトップ版/サーバー版と同じアルゴリズムです

## v2 の変更点
1. **顔認識モデルを 2026may（dynamic-input）に変更**。デスクトップ版の dynamic 処理（32の倍数への埋め込み、粗スケールでの再検出、端・小顔の判定、重複マージ）を移植
2. **画面を `style.css`（ご提供のもの・無改変）で表示**。足りない部品だけを `app.css` に追加
3. **脆弱性対策と堅牢化**（下表）
4. **GitHub Actions は使いません**（`.github/` なし）。公開前のテストは手元で `npm test`
5. 追加機能: 検出精度の選択（高精度/高速）、残り時間の表示、処理停止の自動検知

## 脆弱性対策（詳細は SECURITY.md）
| 対象 | 対策 |
|---|---|
| スクリプト注入（XSS） | CSP（自サイトのファイルのみ許可。インライン・eval・外部サイトは禁止）。HTML を文字列で組み立てず、ファイル名などは `textContent` で表示 |
| 他サイトへの埋め込み | iframe 内では起動しない。Apache では `X-Frame-Options` と `frame-ancestors`（`.htaccess`） |
| モデルの差し替え・改ざん | モデルの SHA-256 を固定。一致しないものは解析器に渡さない（手動で選んだファイルも同じ） |
| ファイルの破損・改ざん | `integrity.json`（全ファイルの SHA-256）を診断ページで照合。ライブラリの出所は `vendor/VERSIONS.json` |
| 悪意のあるファイル名 | 制御文字・向きを変える文字(RLO)・パス区切り・Windows予約名を除去 |
| 不正なメッセージ・巨大な動画 | Worker は受信内容を検証してから処理。解像度（4K相当）・容量（4GB）に上限。2分以上進まなければ停止を検知 |
| 端末への痕跡・外部通信 | 保存領域（localStorage/IndexedDB/Cookie）を使わない。通信は自サイトのモデル取得のみ。外部CDNなし |

## 検証したこと／できていないこと
**自動テストで確認済み**（`npm test`、7スイート）
- **本物のモデル × OpenCV.js（WASM）が、Python(cv2) 実装と同じ検出をする**: 実画像11枚×2設定で件数・位置(差0.000px)・信頼度が一致。顔なし画像に誤ってモザイクを掛けない
- Python 実装との一致: dynamic 検出ロジック（乱数90ケース＋しきい値の境界78ケース）、追跡（2183件の状態）、割当、**モザイクはピクセル単位で一致**、ビットレート
- Mat の解放漏れ無し（生成した Mat を1個単位で追跡）、300〜600フレームでメモリ増加なし
- Worker の処理フロー・入力検証、画面の操作、診断ページ、セキュリティ設定（CSP・禁止API・外部URL・台帳・供給網）
- **テスト自体の信頼性**: 故意にバグ・脆弱性を仕込む「変異テスト」約60種類を全て検出（`tests/mutation_check.py`）

**自動テストでは確認できていないこと**（実ブラウザが必要。設置後に `selfcheck.html` で確認）
- WebCodecs による実際のエンコード/デコード、Mediabunny の実挙動（音声・縦動画の回転・フレーム加工フック）
- ブラウザ上で CSP が実際に効くこと（診断ページが実効を確認します）
- 各ブラウザでの動作と、**その端末での処理速度**

**処理速度の目安**（この開発環境のCPU・1スレッドでの実測。利用者の端末では変わります）
検出1回: 640px 以下で約 80〜150ms、960px で約 300ms。したがって 30fps・1分の動画で、**高精度(960px)は約9〜10分、高速(640px)は約4〜5分**が目安です。診断ページがお使いの端末での実測値を出します。

## 設置
### GitHub Pages（Actions を使わない）
1. 非公開/公開のリポジトリを作り、このフォルダの中身をそのまま push（`node_modules/` は除く。`.gitignore` 済み）
2. Settings → Pages → **Build and deployment: Deploy from a branch** → Branch: `main` / `(root)`
3. Settings → Actions → General → **Disable actions**（任意）。ルートの **`.nojekyll`** があるため、Actions を無効にしていても、ブランチの内容がそのまま公開されます（GitHub の公式ドキュメントに記載。実際の画面で確認してください）
4. 公開された URL（https）で `selfcheck.html` を開いて診断

注意: Pages で公開したサイトは**誰でも開けます**（動画は端末内処理なので動画は漏れませんが、利用は制限できません）。非公開リポジトリでの Pages 公開には有料プランが必要です。HTTP ヘッダーを設定できないため、CSP は meta で指定し、埋め込み防止は JavaScript で行っています。

### さくらのレンタルサーバ / 手元のPC
- さくら: 全ファイルを公開フォルダへアップロードし、**HTTPS を有効**にする。`.htaccess` が使われ、サーバー側でもセキュリティヘッダーを付けます（500 エラーになる場合は `.htaccess` のコメントを参照）
- 手元: このフォルダで `python -m http.server 8000` → `http://localhost:8000/`（`file://` では動きません）
- 公開に不要な `tests/` `tools/` `node_modules/` はアップロードしなくて構いません

## 公開前の手順（毎回）
```bash
npm install            # jsdom（テスト用）のみ。実行時の依存はありません
npm test               # 全テスト。1つでも失敗したら公開しない
# ファイルを変更した場合は、台帳を作り直してから、もう一度テスト
npm run integrity && npm test
npm run verify         # 配置したファイルが台帳と一致するか
```
`npm test` には、台帳が最新でない・CSP が緩んでいる・禁止APIが混入している等を検出する検査が含まれます（Actions の代わりの、手元のゲートです）。

## 設置後に必ず行う: 動作診断
`selfcheck.html` →「診断を開始」。CSP の実効、全ファイルの整合性、モデルの固定ハッシュ、エンコード対応、エンジンの起動、顔検出（顔画像→モザイク）、そして（任意）**実際に使う動画の先頭3秒の変換**と処理速度を確認します。**スマホで撮った縦向きの動画**でも、一度確認してください。結果は画面下のテキストをコピーして問い合わせに使えます。

## 使い方
動画をドロップ（または選択）→ スライダーでモザイクの掛かり具合を確認 → 品質と精度を選んで「動画を出力」→ 再生・ダウンロード。処理中はタブを閉じたり、別のタブに切り替えたりしないでください。

## 既知の制約
- 検出精度は YuNet に依存します。横顔・遠景・強い逆光・マスクでは取りこぼしがあり得ます。**検出解像度を下げる「高速」は、小さい顔を見逃しやすく、顔でない物を誤検出する場合もあります**（実モデルでの検証で、コーヒーカップの画像を 480px で顔と誤検出した例があります）。プライバシー目的の公開前には、必ず出力動画を目視確認してください。
- 入力は mp4 / mov / m4v / webm / mkv（avi・wmv は未対応）。4K相当・4GBまで。長い動画・大容量は端末のメモリ次第です。
- 軽量モードは映像のビットレートで容量（約0.40倍）を狙います。音声は再エンコードしないため、デスクトップ版より大きくなることがあります。
- 可変フレームレートの動画は、元のタイムスタンプを保ったまま処理します。
- 初回は約13MBのライブラリをダウンロードします（以後はキャッシュ）。
